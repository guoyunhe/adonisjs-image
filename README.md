# adonisjs-image

A complete AdonisJS image management package featuring seamless uploads, Drive storage and Lucid ORM integration.

## Features

- Fast, reliable image processing powered by [Sharp](https://sharp.pixelplumbing.com/).
- Sanitized SVG originals with rasterized thumbnails.
- Purpose-specific presets for avatars, general images, high-resolution photos, and more.
- Automatic named thumbnails stored alongside their original images in one table.
- [Drive](https://docs.adonisjs.com/guides/digging-deeper/drive)-compatible storage across local and cloud disks, with private-file URL signing.

## Installation

Requires [@adonisjs/drive](https://docs.adonisjs.com/guides/digging-deeper/drive), [@adonisjs/lucid](https://docs.adonisjs.com/guides/database/lucid), and an existing `users` table.

```sh
pnpm add adonisjs-image
node ace add adonisjs-image
node ace migration:run
```

`node ace add adonisjs-image` generates:

- `app/models/image.ts`
- `app/transformers/image.ts`
- `config/image.ts`
- `database/migrations/<timestamp>_create_images_table.ts`

It also registers the image provider in `adonisrc.ts`. Running `node ace migration:run` generates
`database/schema.ts`.

The image migration references `users.id`, so create the `users` table first. The configure command
does not modify your `User` model or create routes/controller; see the optional avatar and route
examples below. `database/schema.ts`, generated by Lucid after migration, provides the `ImageSchema`
extended by the generated model.

## Image model and table

The generated `Image` model extends Lucid's generated `ImageSchema`. The `images` table stores
original images and thumbnails:

| Property    | Description                          |
| ----------- | ------------------------------------ |
| `id`        | Primary key.                         |
| `parentId`  | Parent image ID; null for originals. |
| `name`      | Thumbnail name; null for originals.  |
| `userId`    | Uploader ID; null if deleted.        |
| `preset`    | Processing preset.                   |
| `disk`      | Drive disk.                          |
| `path`      | Storage path.                        |
| `format`    | Output format.                       |
| `size`      | File size in bytes.                  |
| `width`     | Width in pixels.                     |
| `height`    | Height in pixels.                    |
| `hash`      | SHA-256 hash.                        |
| `createdAt` | Creation time.                       |
| `updatedAt` | Update time.                         |

## Configuration

Edit `config/image.ts` to adjust settings. The top-level `default` selects the preset used
when an upload does not specify one; it defaults to `image`. All image processing options live
inside `presets.image`. Additional named presets inherit unspecified options from `image`, while
their `quality` values are merged by format.

### Preset properties

| Property                | Description                                                                       | Default                                                   |
| ----------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `disk`                  | Drive disk used to store files.                                                   | Drive's configured default disk                           |
| `directory`             | Key prefix inside the disk.                                                       | `images`                                                  |
| `convertTo`             | Raster output format for the original and default thumbnail format.               | Input format                                              |
| `maxWidth`, `maxHeight` | Maximum dimensions for the processed original. Images are never enlarged.         | No resize limit                                           |
| `fit`                   | Resize mode for the original: `cover`, `contain`, `fill`, `inside`, or `outside`. | `inside`                                                  |
| `keepMetadata`          | Preserve metadata instead of auto-rotating and stripping EXIF.                    | `false`                                                   |
| `quality`               | Compression quality from 1 to 100, keyed by format.                               | `jpeg: 80`, `webp: 80`, `avif: 50`, `png: 90`, `tiff: 80` |
| `thumbnails`            | Map of thumbnail names to thumbnail settings.                                     | `{}`                                                      |

SVG originals are sanitized (scripts, event handlers, styles, and external resources are removed)
and kept as vector files unless `convertTo` is set. SVG metadata is retained only when
`keepMetadata` is `true`. Their thumbnails are rasterized as PNG by default. `maxWidth`,
`maxHeight`, and `fit` affect raster originals only when a resize limit is set.
The generated starter config sets its own example limits and includes 1280, 640, and 320 square
cover thumbnails for the default `image` preset; these examples do not alter the `defineConfig`
defaults.

### Thumbnail properties

Each entry in `thumbnails` is an object with these optional properties:

| Property          | Description                                                      | Default                                |
| ----------------- | ---------------------------------------------------------------- | -------------------------------------- |
| `width`, `height` | Output dimensions in pixels.                                     | Unset                                  |
| `fit`             | Resize mode: `cover`, `contain`, `fill`, `inside`, or `outside`. | `cover`                                |
| `format`          | Raster thumbnail output format.                                  | Processed original format; PNG for SVG |
| `quality`         | Compression quality from 1 to 100.                               | Preset quality for the output format   |

Thumbnails are skipped when the source image is smaller than any configured width or height.

## Validator

Use Vine to enforce route-specific file size and extension rules before passing uploaded files to
the image service. Define separate validators for general images and avatars, adjusting the limits
to match each endpoint's policy:

```ts
// app/validators/image.ts
import vine from '@vinejs/vine';

export const uploadImageValidator = vine.compile(
  vine.object({
    image: vine.file({
      size: '10mb',
      extnames: ['jpg', 'jpeg', 'png', 'webp'],
    }),
  }),
);

export const uploadAvatarValidator = vine.compile(
  vine.object({
    avatar: vine.file({
      size: '2mb',
      extnames: ['jpg', 'jpeg', 'png', 'webp'],
    }),
  }),
);
```

Controllers use `request.validateUsing(uploadImageValidator)` or
`request.validateUsing(uploadAvatarValidator)` before calling the service. The processor still
rejects malformed or unsupported image data, but does not enforce an upload size limit or a
route-specific format allow-list. Direct service calls do not apply request validators, so validate
user-provided files before calling `image.upload`.

## Service

Use the image service to upload, process, and manage images. The `image` preset is used by default;
call `use()` to select a named preset:

```ts
import image from 'adonisjs-image/services/main';

import { uploadImageValidator } from '#validators/image';

const { image: file } = await request.validateUsing(uploadImageValidator);
if (!file.tmpPath) throw new Error('Could not read uploaded image');

const img = await image.upload(file.tmpPath, { userId: auth.user!.id });
const photoImages = image.use('photo');
const photo = await photoImages.upload(file.tmpPath, { userId: auth.user!.id });
const url = await image.url(img);
const thumbnailUrl = await image.url(img, 'small');
await image.delete(img);
```

Configure named presets in `config/image.ts` to apply different size, crop, format, quality, and
thumbnail settings for avatars, photos, or other uses. Each uploaded image and its thumbnails record
the preset name used, so generated files can be regenerated later if preset settings change.
Invalid uploads throw `InvalidImageException`.

## Transformer

The configure command generates `app/transformers/image.ts`. Use it to return public image URLs
without exposing storage details such as the Drive disk, storage path, or hash:

```ts
import ImageTransformer from '#transformers/image';

return response.created(await ImageTransformer.transform(uploaded));
```

The transformer includes the original URL, image metadata, and transforms preloaded thumbnails
through the same transformer. It does not load relations; preload or load `thumbnails` before
transforming when thumbnail data is needed.

## Routes and controller

The configure command does not modify `start/routes.ts` or generate a controller. Add the
resource route and create `app/controllers/images_controller.ts` using the following examples:

```ts
// start/routes.ts
import router from '@adonisjs/core/services/router';

import { controllers } from '#generated/controllers';

router.resource('images', controllers.Images).only(['store', 'show', 'destroy']);
```

| Method   | Path          | Purpose                                                                   |
| -------- | ------------- | ------------------------------------------------------------------------- |
| `POST`   | `/images`     | Upload the multipart file in the `image` field.                           |
| `GET`    | `/images/:id` | Get the original image URL; add `?thumbnail=small` for a named thumbnail. |
| `DELETE` | `/images/:id` | Delete an image and its thumbnails.                                       |

Add the authentication and authorization middleware appropriate for your application.

```ts
// app/controllers/images_controller.ts
import type { HttpContext } from '@adonisjs/core/http';
import image from 'adonisjs-image/services/main';

import Image from '#models/image';
import ImageTransformer from '#transformers/image';
import { uploadImageValidator } from '#validators/image';

export default class ImagesController {
  async store({ request, response }: HttpContext) {
    const { image: file } = await request.validateUsing(uploadImageValidator);
    if (!file.tmpPath) {
      return response.badRequest({ message: 'Could not read uploaded image' });
    }

    const uploaded = await image.upload(file.tmpPath);
    return response.created(await ImageTransformer.transform(uploaded));
  }

  async show({ params, request }: HttpContext) {
    const record = await Image.findOrFail(params.id);
    await record.load('thumbnails');
    const transformed = await ImageTransformer.transform(record);
    const thumbnail = request.input('thumbnail');
    return typeof thumbnail === 'string'
      ? { ...transformed, url: await image.url(record, thumbnail) }
      : transformed;
  }

  async destroy({ params, response }: HttpContext) {
    const record = await Image.findOrFail(params.id);
    await image.delete(record);
    return response.noContent();
  }
}
```

## User avatar

### Avatar Configuration

Add an `avatar` preset to `config/image.ts`. It inherits unspecified options from the `image`
preset:

```ts
presets: {
  avatar: {
    directory: 'avatars',
    maxWidth: 512,
    maxHeight: 512,
    fit: 'cover',
    convertTo: 'webp',
    thumbnails: {
      large: { width: 256, height: 256, fit: 'cover', format: 'webp' },
      medium: { width: 128, height: 128, fit: 'cover', format: 'webp' },
      small: { width: 64, height: 64, fit: 'cover', format: 'webp' },
    },
  },
}
```

### Avatar Migration

To associate users with avatar images, add an `avatar_id` column after the `images` table has been
created. Generate a migration:

```sh
node ace make:migration add_avatar_to_users
```

Then add:

```ts
// database/migrations/<timestamp>_add_avatar_to_users.ts
import { BaseSchema } from '@adonisjs/lucid/schema';

export default class AddAvatarToUsers extends BaseSchema {
  protected tableName = 'users';

  async up() {
    this.schema.alterTable(this.tableName, (table) => {
      table
        .integer('avatar_id')
        .unsigned()
        .nullable()
        .references('id')
        .inTable('images')
        .onDelete('SET NULL');
      table.index('avatar_id');
    });
  }

  async down() {
    this.schema.alterTable(this.tableName, (table) => {
      table.dropForeign(['avatar_id']);
      table.dropIndex(['avatar_id']);
      table.dropColumn('avatar_id');
    });
  }
}
```

### Avatar Relationship

Then add this relation to your `User` model:

```ts
// app/models/user.ts
import { belongsTo } from '@adonisjs/lucid/orm';
import type { BelongsTo } from '@adonisjs/lucid/types/relations';

import Image from '#models/image';

export default class User extends compose(UserSchema, withAuthFinder(hash)) {
  @belongsTo(() => Image)
  declare avatar: BelongsTo<typeof Image>;
}
```

### Avatar Routes

Add an endpoint to replace the authenticated user's avatar:

```ts
// start/routes.ts
import router from '@adonisjs/core/services/router';

import { controllers } from '#generated/controllers';
import { middleware } from '#start/kernel';

router
  .group(() => {
    router.put('/avatar', [controllers.Avatar, 'update']);
    router.delete('/avatar', [controllers.Avatar, 'destroy']);
  })
  .prefix('/profile')
  .use(middleware.auth());
```

Protect this route with your application's authentication middleware.

```ts
// app/controllers/avatar_controller.ts
import type { HttpContext } from '@adonisjs/core/http';
import image from 'adonisjs-image/services/main';

import { uploadAvatarValidator } from '#validators/image';

export default class AvatarController {
  async update({ auth, request, response }: HttpContext) {
    const user = auth.user!;
    const { avatar: file } = await request.validateUsing(uploadAvatarValidator);
    if (!file.tmpPath) {
      return response.badRequest({ message: 'Could not read uploaded avatar' });
    }

    const uploaded = await image.use('avatar').upload(file.tmpPath, { userId: user.id });
    await user.related('avatar').associate(uploaded);

    return response.ok({
      id: uploaded.id,
      url: await image.url(uploaded),
    });
  }

  async destroy({ auth, response }: HttpContext) {
    const user = auth.user!;
    await user.load('avatar');
    if (!user.avatar) return response.noContent();

    await image.delete(user.avatar);
    return response.noContent();
  }
}
```
